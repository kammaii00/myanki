# MyAnki 개발 계획

> 작성일: 2026-11-01 · 상태: 0단계 완료, 1단계(카드 관리) 대기

## 1. 목표와 전제
* **목표:** Anki의 핵심 기능만 남긴다. 카드를 입력하면 기억 주기에 맞춰 알아서 복습시키고, 카드 앞면에는 Google TTS 음성을 자동으로 붙인다.
* **전제 (확정):**
  * 혼자 쓰는 개인용 앱이다. 출시는 나중에 따로 검토한다.
  * Android 폰에서만 쓴다.
  * 기존 Anki 카드는 **복습 이력까지** 옮긴다.

## 2. 기술 구성
| 영역 | 선택 | 이유 |
|---|---|---|
| 앱 | Flutter + Riverpod + go_router | podo_speak과 같은 조합이라 익숙함 |
| 로그인 | Firebase Auth (Google 로그인 1개) | 앱을 다시 설치하거나 폰을 바꿔도 데이터 유지 |
| 데이터 | Cloud Firestore (오프라인 캐시) | 자동 백업, 인터넷이 없어도 복습 가능 |
| 음성 파일 | Firebase Storage + 폰 내부 캐시 | 한 번 만들면 이후에는 오프라인 재생 |
| TTS | Google Cloud TTS Chirp 3 HD 음성 | 가장 자연스러운 등급, 매달 100만 자 무료 |
| TTS 호출 | Cloud Functions (Firestore 트리거, TypeScript) | 키를 서버에만 두고, 오프라인에서 만든 카드도 자동 처리 |
| 복습 계산 | FSRS (`fsrs` Dart 패키지) | Anki 23.10부터 들어간 최신 알고리즘 |
| Anki 이전 | Mac에서 실행하는 Python 스크립트 | 한 번만 쓰는 기능이고, Anki 파일(SQLite)은 Python으로 다루기 쉬움 |

**개인용이라 뺀 것:** App Check, 결제, 온보딩, 분석 도구, Play 스토어 등록.

## 3. 데이터 구조 (Firestore)
```
users/{uid}
 ┣ settings            # 목소리, 말하기 속도, 자동 재생, 하루 시작 시각(기본 새벽 4시)
 ┣ decks/{deckId}      # name, newPerDay(하루 새 카드 수), ankiDeckId?
 ┣ cards/{cardId}      # 아래 참고
 ┗ reviewLogs/{logId}  # cardId, rating(1~4), reviewedAt, durationMs, source(app|anki)
```
**cards 문서 필드**
* 내용: `deckId`, `front`, `back`, `tags`, `suspended`(일시정지)
* 음성: `audio { status(pending|ready|failed), path, hash, voice }`
* 복습 상태: `srs { state, step, stability, difficulty, due, lastReview, reps, lapses }`
* Anki 출처: `ankiCardId`, `ankiNoteId` (이전된 카드만 있음)
* 이전된 카드의 문서 ID는 `anki_{Anki 카드 ID}`이다. 그래서 이전 스크립트를 다시 돌려도 카드가 중복되지 않고 덮어쓰기만 된다.

## 4. 음성(TTS) 설계
```
카드 저장(앱) → Firestore 동기화 → Function 트리거
→ 지문(hash)이 바뀌었을 때만 TTS 호출 → mp3를 Storage에 저장
→ audio.status = ready → 앱이 처음 한 번 내려받아 폰에 보관 → 이후 바로 재생
```
* **지문(hash):** 앞면 텍스트 + 목소리 + 속도를 합쳐 만든 값이다. 뒷면만 고친 경우처럼 지문이 같으면 음성을 다시 만들지 않는다.
* **오프라인:** 인터넷 없이 만든 카드는 나중에 동기화되는 순간 트리거가 실행되어 자동으로 처리된다.
* **대량 생성:** Anki 이전 때 수천 장이 한꺼번에 들어오므로, Function 동시 실행 수(`maxInstances`)를 제한하고 실패하면 재시도한다.
* **텍스트 정리:** TTS에 보내기 전에 HTML 태그와 기존 `[sound:...]` 태그를 제거한다.
* **저장 경로:** `users/{uid}/audio/{cardId}_{hash}.mp3`
* **리전:** Function은 서울(Firestore 트리거는 DB와 같은 리전이어야 함), Storage는 미국이다. 문장 하나의 mp3가 수십 KB라 리전 간 전송 비용은 무시할 수준이고, 앱은 처음 한 번만 내려받아 캐시하므로 속도 차이도 체감되지 않는다.

## 5. 복습(SRS) 설계
* **알고리즘:** FSRS를 쓰고 목표 기억률은 90%(Anki 기본값)로 둔다.
* **하루 기준:** 새벽 4시(Anki 기본값과 같음). "오늘 복습"은 다음 날 새벽 4시 전에 예정된 카드다.
* **오늘의 큐:** 학습 중 카드(분 단위) → 복습 예정 카드 → 새 카드(덱마다 하루 한도까지).
* **복습 화면:** 앞면 표시 + 음성 자동 재생 → [정답 보기] → 뒷면 → [다시/어려움/좋음/쉬움]. 버튼마다 다음 간격("10분", "3일")을 보여준다.
* **저장:** 버튼을 누르면 카드의 `srs` 갱신과 `reviewLogs` 추가를 한 번의 batch로 함께 쓴다.
* **테스트:** 현재 시각을 바꿔 넣을 수 있게(시계 주입) 만들어, 날짜를 바꿔 가며 간격을 검증한다.

## 6. Anki 이전 (복습 이력 포함)
`tools/anki_migrator/`에 둘 Python 스크립트로 진행한다.

1. **내보내기:** Anki(또는 AnkiDroid)에서 컬렉션 패키지(.colpkg)로 내보낸다. "구버전 Anki 지원"을 체크하고 미디어는 뺀다. 체크하는 이유는 스크립트가 한 가지 파일 형식만 읽으면 되기 때문이다.
2. **점검 모드 (`--dry-run`):** 업로드는 하지 않고 아래 내용만 출력한다. 이 숫자를 Anki 화면과 비교한다.
   * 덱·노트 유형별 카드 수, 샘플 카드 10장, 오늘 복습 예정 수, 음성으로 만들 총 글자 수
3. **변환:**
   * 내용: 노트 필드(구분자 `0x1F`)에서 앞면·뒷면을 꺼내고 HTML을 정리한다.
   * 복습 상태: Anki에서 이미 FSRS를 쓰고 있었다면 카드의 `data`에 있는 `s`/`d` 값을 그대로 쓴다. SM-2를 썼다면 복습 기록(revlog)을 시간순으로 FSRS에 다시 넣어 상태를 계산한다.
   * **다음 복습일은 Anki 값을 그대로 유지한다.** 전환하는 날 복습이 한꺼번에 몰리거나 갑자기 비지 않게 하기 위해서다.
   * 일시정지 카드는 그대로 유지하고, 복습 기록은 `reviewLogs`(source: anki)로 옮긴다.
4. **업로드:** Firebase Admin SDK로 올린다. 문서 ID가 고정이라 여러 번 실행해도 안전하다.
5. **음성:** 올라간 카드는 `audio.status = pending` 상태이고, Function이 자동으로 생성한다.
6. **검증:** 앱의 "오늘 복습 수"가 Anki와 같은지 확인하고, 무작위 카드 10장의 다음 복습일을 비교한다.

**전환 시점:** 개발하는 동안에는 Anki를 계속 쓴다. 앱이 완성되면 마지막으로 한 번 더 내보내 스크립트를 다시 돌리고, 그날부터 앱만 쓴다.

**미리 확인할 것**
* **앞면 언어 (확인 완료):** 기존 Anki 카드의 앞면은 모두 영어다. 그래서 음성은 항상 앞면에 붙인다. 점검 모드에서는 앞면에 한글이 섞인 카드가 있는지만 다시 확인한다.
* **FSRS 버전 일치:** 스크립트의 py-fsrs와 앱의 Dart `fsrs`가 같은 알고리즘 버전(파라미터 21개)이어야 한다. 버전이 다르면 계산 결과가 어긋난다.
* **오래된 기록:** 수동으로 일정을 바꾼 기록(버튼 0)은 제외한다. 구 스케줄러 시절에는 학습 단계 버튼이 3개였으므로 그 의미 차이를 보정한다.

## 7. 개발 단계
| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **0. 준비** | Flutter·Firebase 프로젝트 생성, TTS API 켜기, Google 로그인 | 에뮬레이터와 폰에서 로그인까지 됨 |
| **1. 카드 관리** | 덱·카드 추가/수정/삭제, 목록, 검색, 일시정지 | 카드가 저장되고 재설치 후에도 남아 있음 |
| **2. TTS** | Function 트리거, Storage 저장, 캐시 재생, 실패하면 재시도 | 카드 저장 후 몇 초 안에 앞면 재생, 비행기 모드에서도 재생 |
| **3. 복습** | FSRS 연결, 오늘의 큐, 복습 화면, 하루 한도 | 시계를 바꾼 테스트로 간격 검증 통과 |
| **4. Anki 이전** | 점검 모드 → 변환 → 업로드 → 음성 일괄 생성 | 오늘 복습 수와 샘플 다음 복습일이 Anki와 일치 |
| **5. 다듬기** | 목소리 미리듣기·선택, 0.75배속, 스트릭·통계, 복습 알림 | 매일 쓰기에 불편함이 없음 |

1~3단계가 핵심 MVP다. 4단계까지 끝나면 Anki를 대체할 수 있다.

## 8. Android 설치와 업데이트
* **개발:** 에뮬레이터에서 개발하고, 실제 폰은 USB 디버깅으로 확인한다.
* **설치:** Play 스토어 없이 직접 서명한 APK를 폰에 설치한다.
* **Google 로그인:** 디버그 키와 릴리스 키의 SHA-1을 모두 Firebase에 등록한다. 빠뜨리면 로그인이 실패한다.
* **업데이트:** 새 APK를 덮어쓰기로 설치한다. 같은 서명 키가 있어야 하므로 키 파일을 반드시 백업한다.

## 9. 비용과 안전장치
* Cloud Functions를 쓰려면 Blaze 요금제가 필요하고, TTS를 쓰려면 결제 계정이 필요하다. 둘 다 카드 등록은 필요하지만 개인 사용량은 무료 범위다.
* 이전에 필요한 글자 수는 점검 모드에서 미리 계산한다. 100만 자를 넘으면 나눠서 생성한다.
* GCP 예산 알림을 설정한다(예: 월 $5).
* Firestore·Storage 규칙은 본인 uid만 읽고 쓸 수 있게 한다.
